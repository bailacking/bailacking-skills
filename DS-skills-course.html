② 三个能力包逐个讲

🔍 verify · 验证闭环 G3

它干啥：任何代码改完之后，必须自动跑通 测试 → lint → 类型检查，全绿了、有客观证据，才算「完成」。不准「编译过了就报完成」。

输入刚改完的代码 + 项目里的测试/lint 配置
处理跑测试 → 跑 lint → 跑类型检查 →（跑构建）→ 失败就 读错→修→重跑
输出「完成 / 未完成」的客观结论

💡 大白话：像厨师做完菜必须亲口尝一口，不能「看颜色差不多就端上桌」。这是专门治 vibe coding（随手写代码）最容易犯的「假完成」毛病。

♻️ reuse-eval · 开源复用评估 G5

它干啥：要写某个功能前，先去 GitHub 搜现成的开源项目，评估能不能用，再决定要不要下载——而且下载要你点头（「确认执行」）。

输入一个需求（比如「我要做个 XX」）
处理检索 → 评估候选（许可证红线 / 活跃度 / 适配成本 / 功能匹配）→ 出对比表+方案 → 等你确认
输出候选对比表 + 推荐方案

🚫 红线：GPL / AGPL 这类「传染性」协议，若涉及闭源商用直接排除；绝不擅自下载整合进你的项目。

💡 大白话：像买家具先比价、看评价，不贸然下单；而且「下单」这一步必须你点头。

📖 codebase-course · 代码可视化课程 G7+G8

它干啥：把你的代码库变成你能读懂的 HTML 课——目录树白话、模块讲解、流程图、术语表，专治「看不懂自己代码」。

输入一个代码库（这次：它自己讲的这三个 skill）
处理摸结构 → 读关键文件 → 白话转译 → 生成 HTML 课
输出交互式 HTML 课程（你正在看的这页）

💡 大白话：像给一台机器配一本「给小白看的使用说明书」。你刚让我用它来讲它自己，所以这篇就是个活例子。

④ 术语表（看不懂的词在这）

Skill（能力包）：DS 的能力包，核心是 SKILL.md 指令文件，按需加载、不独立运行。
SKILL.md：每个 skill 的「说明书」，写清楚何时用、怎么做。
lint（代码体检）：自动检查代码风格和潜在小毛病的工具，类似「作文批改」。
测试（test）：自动检查代码行为是否符合预期的脚本，跑通了说明没改坏。
类型检查：检查变量类型（数字/文字/列表…）有没有用对的工具。
许可证（license）：开源代码的「使用合同」。MIT / Apache 宽松；GPL / AGPL 传染性——改了往往得连带开源，闭源商用要避开。
开源复用：用别人已经写好的代码，而不是自己从零重写（不重复造轮子）。
验证闭环：写完 → 测 → 报错 → 修 → 再测 的循环，直到全绿。
vibe coding：用大白话指挥 AI 写代码的方式；快但容易「假完成」「看不懂自己代码」。这三个 skill 就是给它的「安全带」。
